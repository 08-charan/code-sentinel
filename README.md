# CodeSentinel (`code-sentinel`)

[![Code Style: Black](https://img.shields.io/badge/code%20style-black-000000.svg)](https://github.com/psf/black)

A terminal-native AST static analysis engine, Git working tree inspector, and AI code preference evaluation harness. Designed for developers building substantial software systems who prioritize algorithmic correctness, security invariants, and explicit engineering trade-offs over guesswork.

---

## Architecture Overview

```
                      +---------------------------------------+
                      |       Terminal CLI (Click / Rich)     |
                      +---------------------------------------+
                                          |
                +-------------------------+-------------------------+
                |                                                   |
      [ Static Analysis Engine ]                             [ Git VCS Inspector ]
                |                                                   |
    +-----------+-----------+                               +-------+-------+
    |           |           |                               |               |
 [AST McCabe] [Security] [Trade-Offs]                [Staged Diff]    [Working Tree]
 (Complexity) (Vulns)   (O(N^2), Mem)                       |               |
    +-----------+-----------+                               +---------------+
                \           /                                       |
                 v         v                                        v
        +---------------------------------------------------------------+
        |              AI Preference & Evaluation Engine                |
        |  (Syntactic Invariants, AST Density, Complexity Delta scoring) |
        +---------------------------------------------------------------+
```

### Core Design Principles
1. **Zero External Network Dependencies during Core Analysis:** Static analysis, AST walks, and vulnerability scans run 100% locally in your terminal or CI environment.
2. **Explicit Engineering Trade-Offs:** Rather than generic linting rules, CodeSentinel reasons about computational complexity ($O(N^2)$ vs $O(N)$), memory re-allocation pitfalls, and error boundary suppression.
3. **AI Coding Assistant Evaluation Harness:** Built-in evaluation routines to benchmark competing AI code generations (Model A vs Model B) across AST validity, cyclomatic complexity, and idiomatic constraints.

---

## Key Features

- **AST-Based Cyclomatic Complexity Profiler:** Traverses abstract syntax trees to calculate exact McCabe complexity scores per function/coroutine, highlighting maintainability bottlenecks before merge.
- **AST Security & Bug Hazard Scanner:** Identifies dangerous dynamic evaluations (`eval`, `exec`), command injection paths (`shell=True`, `os.system`), insecure deserialization (`pickle`), and bare exception masking.
- **Algorithmic Trade-Off Evaluator:** Detects nested loop scaling hazards ($O(N^2)$), in-loop immutable string reallocations, and recommends space/time optimizations.
- **Git VCS Integration:** Inspects staged files (`git diff --cached`) directly in the terminal before commit.
- **Dual-Model Preference Benchmark:** Evaluates competing LLM code outputs, providing automated scoring and engineering justification for preference datasets.

## Installation & Setup

### Prerequisites
- Python 3.10 or higher
- Git installed and available on `PATH`

### Local Setup
```bash
# Clone the repository
git clone https://github.com/08-charan/code-sentinel.git
cd code-sentinel

# Create and activate virtual environment
python -m venv venv
# On Windows:
venv\Scripts\activate
# On Linux/macOS:
source venv/bin/activate

# Install dependencies in editable mode
pip install -e .
```

## Terminal CLI Usage

### 1. Analyze a File or Codebase
Run comprehensive AST and complexity analysis on any target module or folder:
```bash
code-sentinel analyze sentinel/
```
Enforce a minimum maintainability score for CI/CD gates:
```bash
code-sentinel analyze sentinel/ --min-score 75
```

### 2. Inspect Staged Git Changes
Run pre-commit analysis on only the files staged in Git:
```bash
code-sentinel diff --staged
```

### 3. Evaluate AI Code Preference (Model A vs Model B)
Compare two candidate implementations generated by an AI assistant:
```bash
code-sentinel eval-pref --file-a solution_a.py --file-b solution_b.py --prompt "Implement LRU Cache"
```

## Engineering Trade-Offs & Decisions

| Decision | Alternative Considered | Selected Approach | Trade-Off Rationale |
| :--- | :--- | :--- | :--- |
| **AST Tree Traversal** | Regex-based token scanning | Python standard library `ast.NodeVisitor` | AST parsing handles arbitrary nesting, comments, and whitespace accurately, avoiding false positives inherent in regex token matching. |
| **Terminal Output** | Plain ASCII text / JSON only | Rich Console tables & panels | Structured visual feedback in terminal improves developer debugging speed while maintaining optional JSON machine-readability. |
| **Git Integration** | Pure subprocess shell calls | GitPython + bounded subprocess fallback | Minimizes external binary dependencies while retaining robust support across Windows, macOS, and Linux terminals. |
| **Evaluation Strategy** | External LLM API judge | Deterministic AST & complexity metrics | Deterministic scoring eliminates latency, token costs, and API rate limits while guaranteeing repeatable ground-truth evaluations. |
